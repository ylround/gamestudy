# 战斗与答题节奏设计

## 1. 参考的市面做法

Prodigy Math 的核心战斗是**回合制答题**：玩家选择法术/行动，随后回答一道数学题；答对时法术命中，答错时怪物反击。题目不是独立页面，而是“出招”这一回合的一部分；战斗动画负责把判题结果即时翻译成可理解的动作反馈。

参考资料：

- [Prodigy Math: Battling in Prodigy Math](https://prodigygame.zendesk.com/hc/en-us/articles/12910978061844-Battling-in-Prodigy-Math)（官方帮助中心，说明战斗为回合制、答题驱动）
- [Prodigy Math Game - Wikipedia](https://en.wikipedia.org/wiki/Prodigy_Math_Game)（产品机制概述）

我们没有复制 Prodigy 的美术、代码或题目；只参考“答题即行动、动作即反馈”的交互节奏，角色、怪物、法术、题目和动画均为原创或生成内容。

## 2. 本项目的回合循环

```text
你的回合 · 答题施法
   └─ 读题 → 可看提示 → 选择/输入 → 提交（服务端判题）
        ├─ 答对：法术飞向怪物 → 命中闪光/受击抖动 → 伤害数字 → 怪物扣血
        └─ 答错：怪物扑向勇者 → 勇者受击闪光/抖动 → 伤害数字 → 勇者扣血
   └─ 反馈卡展示正确答案与解析 → 继续 → 下一题 / 结算
```

设计取舍：

- **题目就是行动，不额外加“先选攻击再答题”的一步**。低龄玩家每多一次点击就多一个流失点；答题本身承担“出招”功能，和 Prodigy 的回合循环一致。
- **战斗场景固定在答题卡上方**，答题卡内部滚动，不再把战斗场景顶出屏幕。玩家答题、看解析、点继续时始终能看到怪物血量和角色状态。
- **动画只呈现已发生的服务端结果**。前端不会自己算伤害或胜负；动画是服务端判题结果的视觉翻译。
- **反馈优先于炫技**：动画不遮挡题干/提交按钮；反馈卡显示正确答案和解析；减少动态效果时直接关闭飞行/闪光/伤害数字。

## 3. 动画清单

| 事件 | 表现 |
| --- | --- |
| 答对 | 勇者前冲蓄力，法术球从勇者飞向怪物（带拖尾），怪物白闪/抖动/后退，`-N` 伤害数字，怪物血条平滑扣减；连击显示 `×N`。 |
| 答错 | 怪物前扑，红色法术球飞向勇者，勇者红闪/抖动，`-N` 伤害数字，勇者血条扣减；反馈卡显示正确答案。 |
| 连击 | 第 2/3/4 连击伤害递增，金色连击数字弹出。 |
| 怪物死亡 | 怪物受击后下沉、旋转、淡出；结算按钮仍可点击。 |
| 勇者失败 | 勇者受击后倒下淡出。 |
| 提示 | 提示卡滑入；提示次数由服务端扣减。 |
| 阶段 | 工具栏显示“你的回合 · 答题施法 / 施法命中 / 怪物反击 / 胜利 / 战败”。 |

## 4. 布局与无障碍

- 战斗页高度 = 视口高度 − 实际顶栏高度（JS 测量 `--topbar-height`），战斗区 `flex: 1`，答题卡最大高度受视口约束并内部滚动。
- 1440×900、1024×768、768×900、390×844、320×700 下：`scrollY = 0`，战斗区和答题卡均在视口内；320px 时工具栏压缩为单行。
- `prefers-reduced-motion` 或设置中的“减少动态效果”会关闭飞行物/闪光/伤害数字，保留血条与文字反馈。
- 所有动画仅使用 `transform/opacity/filter`，不改变布局；动画期间按钮仍可操作的范围由反馈卡控制。

## 5. 验收方式

`node e2e/run.mjs` 中包含专门检查：

- 答题前和答题后 `window.scrollY === 0`；
- `.arena` 与 `.question-panel` 的 `getBoundingClientRect()` 均在视口内；
- 提交后存在 `.fx-projectile`、`.fx-impact`、`.fx-damage`，且 `.battle-phase` 显示当前阶段；
- 答错时 `.fx-projectile--monster` 与怪物反击阶段正常。

`node e2e/layout.mjs` 在五种视口重复上述几何检查。
